## Android / iOS

Android 创建 `AndroidLocationClient(context)`，iOS 创建 `IosLocationClient()`，公共入口 `LocationClient.currentLocation(options)`。Android 监听存在且授权允许的 GPS/网络 Provider，请求期间启用的 Provider 会继续投递，接收第一份合格位置；iOS 每次请求独占 CLLocationManager/delegate，平台操作内部切主线程。

Android Manifest 按需声明 `ACCESS_COARSE_LOCATION` / `ACCESS_FINE_LOCATION`；iOS Info.plist 填写 `NSLocationWhenInUseUsageDescription`。调用前由宿主主动取得权限。库不把粗略授权直接判失败，只有位置满足精度才成功；Android API30+ 可接收 GPS 的系统模糊化位置，API24–29 粗略授权仅使用网络。无需背景授权。

`LocationOptions` 默认超时 12 秒、最大缓存年龄 300 秒、最大误差 500 米；`timeoutMillis` 在 `1..Int.MAX_VALUE`，`maxAgeMillis` 非负，`maxAccuracyMeters` 为有限非负值。坐标保持系统原始坐标系，Unix 毫秒时间；非法经纬度、未来/过期坐标、负值或超标精度拒绝。业务需要严格精度时自行设置。

请求协程与页面生命周期绑定。完成、超时和取消都清理系统监听；外部取消继续传播，不转换为普通失败。无合格位置返回 `TimedOut`，系统错误可能返回 `Unavailable`。

## HarmonyOS 原生

OHPM 安装见 README。原生 ArkTS 入口如下；Kotlin/Kuikly 桥自历史0.1.1提供，原生 HAR 保留已发布 `1.0.0`：

```typescript
import { LocationClient, LocationOptions } from '@gycrosskit/location-native';
const client = new LocationClient();
const options = new LocationOptions();
options.maxAccuracyMeters = 100;
const request = client.currentLocation(options);
// 将 request 保存到页面；页面销毁时调用 request.cancel()。
const result = await request.result;
```

在 `module.json5` 声明并由宿主申请 `ohos.permission.APPROXIMATELY_LOCATION`；精确定位另加 `ohos.permission.LOCATION`。`status` 为 `available / permission_missing / service_disabled / timed_out / unavailable / cancelled`；成功的 `fix` 含纬度、经度、精度、Unix 毫秒时间。取消结果为 `cancelled`，重复 cancel 幂等。

每个 client 只在内存缓存上次成功位置；读取缓存时仍重新检查权限、服务、时效、精度，不持久化坐标。页面生命周期由宿主管理，本库不启动后台服务或持续监听。

平台参考：[Android LocationManager](https://developer.android.com/reference/android/location/LocationManager)、[Apple CoreLocation](https://developer.apple.com/documentation/corelocation)、[OpenHarmony LocationKit](https://gitee.com/openharmony/docs/blob/master/zh-cn/application-dev/reference/apis-location-kit/js-apis-geoLocationManager.md)。

取消接线：GycLocationModule 在 cancelLocation 命中 requestId 时同步撤销 active/id，再停止原生 listener；
下一请求可在同一调用批次立即开始，不等待旧 Promise microtask。旧结果不再回调。
Kotlin await 完成后再检查 disposed，阻止已 resume 但尚未交付的 Available 在页面销毁后返回。

此版本的桥接 watchdog 按请求期限加 2 秒回执余量，且不短于 bridgeTimeoutMillis；到期返回 TimedOut，原生空回执仍为 Unavailable。当前 10 秒定位/12 秒 bridge 参数不变。

## Android/iOS Kuikly Native Module

Maven 候选为 `1.0.1`，公开 API 与 `1.0.0` 保持；仅修复 Android 粗略定位与 Provider 切换。未变化的 iOS Git Pod `GycLocationKuikly/Kuikly` 使用精确 tag `1.0.0`，HAR 继续 `1.0.0`。Android API24+、iOS14+；Kotlin handler 由宿主已有 Shared framework 导出，新 Maven 的远程消费须单独验证。

Android 在宿主已有 `registerExternalModule` 接入点注册：

```kotlin
import io.github.gycrosskit.location.kuikly.registerLocationModule

// exports 是真实 IKuiklyRenderExport；每个 Renderer 由 SDK factory 新建 receiver。
exports.registerLocationModule(locationClient)
```

Android 注入 `AndroidLocationClient(context)`；iOS handler 复用 `IosLocationClient`。本库不申请权限、不提供地理编码或坐标转换。每个请求的监听和 deadline 仍由 core 管理；取消保持 CancellationException。Android/iOS 原生默认12秒；OHOS 宿主传10秒 native deadline 时保留默认12秒 bridge预算。

iOS 安装可选原生 Pod subspec，将 `location-kuikly` 导出到宿主既有 Shared framework，随后在创建 Renderer 前于 Main 装配：

```kotlin
// 沿用宿主已有 framework，不新建组件 framework；依赖须为 api 才能 export。
commonMain.dependencies {
    api("com.github.gycrosskit.location:location-core:1.0.1")
    api("com.github.gycrosskit.location:location-kuikly:1.0.1")
}
// 放入宿主已有 iOS framework 配置：
export("com.github.gycrosskit.location:location-core:1.0.1")
export("com.github.gycrosskit.location:location-kuikly:1.0.1")
```


```ruby
# receiver 源码未变，沿用已发布的精确 Git tag；与新 Maven 分别验证。
pod 'GycLocationKuikly/Kuikly', :git => 'https://github.com/gycrosskit/location.git', :tag => '1.0.0'
```

```swift
import GycLocationKuikly
import Shared // 按宿主既有 framework 名称导入

GycLocationModule.configure {
    let handler = IosLocationModuleHandler()
    return (call: handler.call, dispose: handler.dispose)
}
```

`configure` 显式引用确切 `@objc(GycLocationModule)`，SDK 按名称为当前 Renderer 创建 receiver；工厂每次创建新 handler。宿主仅提供既有能力和方法引用，不写 JSON、状态映射或取消 transport。Swift receiver 的 `invalidate` 立即失效，Main 异步释放，不阻塞 SDK 线程；Kotlin handler 在 Main 执行，JSON 字符串回执经 SDK ContextQueue 沿当前 callback 返回。实例不可跨 Renderer 复用。未配置 factory 或缺少 rootView 不会运行原生能力；未做设备与远程发布验收。
