## 本地行为检查

以下命令从仓库根目录执行。配置`ANDROID_HOME`与可运行Gradle的JDK；Kotlin/Native测试需要macOS、Xcode及iOS Simulator运行环境。Node测试转译真实ArkTS源码并使用受控SDK替身，`TYPESCRIPT_PATH`可指定已有TypeScript模块。

```sh
bash gradlew :location-core:jvmTest :location-core:iosSimulatorArm64Test --max-workers=1
bash gradlew :location-core:testDebugUnitTest --tests '*AndroidLocationDeadlineTest' --max-workers=1
bash gradlew -p verification-kuikly test --max-workers=1
node ohos/tests/location.test.cjs
```

只运行受影响目标；需要确认本轮真实执行时加`--rerun-tasks`，不要把`UP-TO-DATE`算成新执行。平台测试结果XML位于`location-core/build/test-results/`；独立Module测试结果在`verification-kuikly/build/test-results/test/`。这些测试不调用真实分享、认证、拨号或定位业务。

## 原生产物与独立消费

HarmonyOS工具链需要DevEco SDK、ohpm与hvigorw。在`ohos/`目录执行：

```sh
ohpm install --all
hvigorw --mode module -p module=LocationNative@default -p product=default assembleHar --no-daemon
```

安装与公开API消费工程按[接入指南](接入指南.md)和[README](../README.md)执行。构建/本地HAR消费不等于OHPM Registry或本版远程消费。Maven、Swift/Pod与HAR按各自版本验证。

## Native Module 候选检查

```sh
bash gradlew -p verification-kuikly test --max-workers=1
bash gradlew :location-kuikly:compileReleaseKotlinAndroid :location-kuikly:compileKotlinIosSimulatorArm64 --max-workers=1
# 发布到库内 staging 后，独立 verification-consumer 按 locationRepository / locationVersion 消费。
```

`GycLocationKuikly/Kuikly` 依赖真实 OpenKuiklyIOSRender 2.28.0，Swift receiver 必须用该 SDK 编译；不能用空 protocol 替身证明链接。source CI 在现有 native job 执行；远程不可变 tag 的 Git Pod 消费、设备权限/相机/定位仍是独立证据。

```sh
products=$(bash scripts/ci-build-kuikly-render.sh "$PWD/build/native-render" GycLocationKuikly/Kuikly)
bash scripts/verify-kuikly-module.sh "$products"
bash scripts/verify-kuikly-assembly.sh "$products"
```

生命周期检查链接真实 Pod 与 SDK，执行真实 SDK `hrv_call` 接口、重复失效、排队调用、迟回调与 `TDFBaseModule.dealloc`；测试 handler 为受控闭包，rootView 为占位 UIView，不启动业务 Renderer。装配检查仅将本库候选发布到仓库内 staging，再从独立 consumer 导出 core/kuikly，使用生成的 Kotlin header 编译 Swift `call`/`dispose` 方法引用；不作为远程 Maven 或 Git Pod 消费证据。
